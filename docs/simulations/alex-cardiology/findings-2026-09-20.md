## Confirmed findings and follow-up

1. **Daily LLM capacity was the main answer blocker.** Before the test, today's
   counters were 41 requests and **83,968 reserved output tokens**. Five new
   admitted turns reserved 2,048 each, ending at 46 requests and **94,208 tokens**.
   Another reservation would reach **96,256**, exceeding the configured **96,000**
   token limit, despite being far below the 500-request limit. The server checks
   the sum of reservations, not actual completion-token usage
   ([admission code](../../../platform/api/src/pms_api/modules/llm.py)).
   Review intended quota/reservation policy before changing capacity; do not
   treat every limit as upstream model unavailability.

2. **Rapid speech submissions hit upstream HTTP 429.** PMS retained 66 failed
   speech requests with `llm_busy`. The Azure speech adapter passes the provider
   response through the shared LLM status mapper, which maps HTTP 429 to that code
   ([speech adapter](../../../platform/api/src/pms_api/integrations/whisper_cloud.py),
   [status mapper](../../../platform/api/src/pms_api/integrations/llm/client.py)).
   Thus an LLM-named error occurred during transcription. Exact upstream
   rate/capacity reasons and `Retry-After` were not retained. Review provider-aware
   pacing/backoff and speech-specific error naming using this baseline.

3. **Readiness can reject a question before audio capture.** Question 1 failed
   after about 5.1 seconds with `PMS: llm_unavailable`; question 2 proceeded normally.
   The controller checks speech and response readiness concurrently. This run did
   not isolate which provider's readiness call failed. The five-second health
   timeout/network-error mapping is consistent with the observed failure, but the
   exact network cause is unverified.

4. **PMS still transcribes questions after answer capacity is exhausted.** Thirteen
   successful transcriptions were followed by `llm_daily_limit`. The desktop
   displays the raw `PMS: llm_daily_limit` message. Consider exposing actionable
   capacity status before the next speech submission. The 13 rejected response
   attempts had no stored response request, so status lookup returned `not_found`;
   that is admission rejection rather than an uncertain provider submission.

The application was left on the requested English chest-discomfort selection.
Only test-owned services were stopped. No application code, provider settings,
quotas, retry rules or credentials were changed as a fix. Existing unrelated
failures in the before/after database summaries are historical, not new failures
from this run.
